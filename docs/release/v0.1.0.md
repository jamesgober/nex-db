# nex-db 0.1.0 - Walking skeleton

The first working build: an embedded database with two engines on one commit log. Not published to crates.io; the API and file formats change before 1.0.

## What it does

- **One commit log** on wal-db, with a record per commit that holds one section per engine it touched. One sequence of commit numbers; a commit becomes visible only after every engine applied it.
- **Atomic commits across engines:** `db.commit(|tx| ..)` signs a user up (an account in the auth engine and a profile page in the content engine) as one commit, or not at all. Snapshot isolation with up to four attempts on conflict.
- **Auth engine:** `hash_password` (Argon2id), `create_account`, `issue_session`, `validate`, `revoke`, `sign_in`. Tokens and identifiers are stored only as keyed BLAKE3 digests.
- **Content engine:** `create`, `get`, and `resolve(site, path)`.
- **Recovery:** opening replays the log into every engine. The database stays closed on a sequence gap, a damaged record, a missing key file, or a store that holds a commit the log does not have.
- **One owner per directory:** a second open fails with `Error::Locked`.

## Checked

- The local gate (format, lints, tests in three feature sets, docs, package) on Windows and Linux, stable and Rust 1.85, and CI on Linux, macOS, and Windows (x64 and ARM).
- The kill test: a writing process killed at random points, 10,000 iterations on Linux and on Windows, every reopen matching the last acknowledged commit.
- `examples/site.rs` on Windows and Linux, including a run stopped without closing the database and the run after it.

## Try it

```text
cargo run --example site
cargo run --example site -- --crash
cargo run --example site
```

## Known limits

- Sessions live in memory and are rebuilt from the whole log at open; there are no checkpoints or log truncation yet.
- Auth sections in the log and the account store are not encrypted yet.
- A damaged record in the middle of the log is caught only when a store holds a later commit (closed in 0.2 with wal-db 1.1).
