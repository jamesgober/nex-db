# nex-db 0.2.0 - Design lock

The public API through 1.0 is written down and approved, and the byte formats are drafted. Not published to crates.io.

## What it adds

- **`docs/API.md`:** every public item planned before 1.0, Tier 1 first, with the version it arrives in and its grade. The examples for what exists run as doctests. Approved on 2026-11-05 after a review against the requirements; changes from here need a recorded decision.
- **`docs/LOG_FORMAT.md` and `docs/FILE_FORMATS.md`:** the commit log record and every file in a database directory. Drafts until 1.0, frozen for 1.x from then.
- **The engine contract** as documented internal code. The commit pipeline, recovery, and the catalog reach engines only through it; a toy engine in the tests runs on the core with no other engine present.

## Changed

- **Catalog format 2:** a collection keeps its engine's definition. A database written by 0.1 does not open; delete its directory.
- **wal-db 1.1, strict open:** only an unfinished last record is cut. Damage before it, or a missing segment, keeps the database closed and leaves the log unchanged.
- crypt-io 1.2.2.
- `AuthTx::revoke` takes `impl AsRef<str>`, like `Auth::revoke`.

## Fixed

- The first sign-in of a process costs the same work whether the identifier exists or not.
- On Unix with Rust below 1.89, a database whose owner had crashed stayed locked on systems without `/proc` (macOS).

## Checked

The local gate on Windows and Linux (stable and Rust 1.85), CI on Linux, macOS, and Windows (x64 and ARM), and the kill test with strict open on Windows and Linux.
