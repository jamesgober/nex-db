# nex-db 0.3.0 - Core and auth

The commit pipeline and the auth engine as planned for 1.0, short of named realms and split auth. Not published to crates.io.

## What it adds

- **Group commit:** one writer appends and syncs each batch, commits apply in sequence order, and a failed write, sync, or apply stops further writes. At most 4,096 commits wait at once (`Error::Busy` beyond).
- **Snapshots:** `Database::read` reads every engine at one sequence number. A snapshot older than 60 seconds fails with `Error::SnapshotTooOld`.
- **Checkpoints and log truncation:** the log stays bounded (`Builder::checkpoint_every`, 64 MiB by default) and an open replays only what came after the last checkpoint.
- **Sealing:** auth sections in the log are encrypted and padded, account records in the account store are encrypted, and the session checkpoint is sealed. The root key can live outside the database directory (`Keys::file`, `Keys::env`); the wrong key fails as `KeyUnavailable`.
- **Accounts:** `revoke_all` (sign out everywhere), `rotate`, `verify_password`, `standing` and `set_standing`, and lock-out after ten failed sign-ins in fifteen minutes.
- **Sessions:** an idle limit, a recheck time, and a payload of up to 256 bytes. Sessions live in a fixed-slot table read without locks; expired sessions and old revocations are reclaimed about a second after their time. `Builder::max_sessions` (1,000,000 by default).
- **Audit chain:** every security write is appended to `auth/audit.chain` (keyed BLAKE3), kept after the log is truncated.

## Changed

- Auth sections are format 2 (sealed). Logs and stores written by 0.1 and 0.2 still read.
- wal-db 1.1.1.

## Fixed

- A damaged time value in stored data could panic when read.

## Not yet

- Named realms, `commit_serializable`, and catalog locks arrive in 0.4; the revocation journal in 0.5.
- The milestone's exit, James's site signing users in, waits for the site's adapter in 0.4. `examples/site.rs` signs users in on every platform in the meantime.
