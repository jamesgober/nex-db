# nex-db 0.4.0 - Content and adapters

The content engine as planned for 1.0 short of search and assets, the auth calls an application's sign-in and session layers need, named realms and spaces, and serializable commits. Not published to crates.io.

## What it adds

- **Drafts and publishing:** entities start as drafts with one working draft each; `save_draft`, `save_revision`, `publish` (a new revision only when the draft changed), `unpublish`, statuses (draft, review, published, archived, trashed), and visibility (public, members, private). Moving a published page leaves a 301 from the old path.
- **Locales:** per-locale drafts, revisions, publishing, and paths; fallback chains per space (`SpaceSpec`), and `Entry::fallback` when another locale was served.
- **Types:** declared field kinds checked on save, unique fields among published values, singletons, reference fields with `Restrict`, `Detach`, or `Cascade` on delete, and terms fields.
- **References:** every entity reference in a draft or published body is indexed in the same commit; `referenced_by` is one read, and `delete` applies each referring field's rule.
- **Trash, restore, delete:** a trashed or deleted entity's paths answer `RouteKind::Gone` (410).
- **Listings:** published entities by site and type, newest first by first publication or by the last publish, with cursors that travel in a URL; filtered by author (`by_author`) or by an entity referred to (`term`).
- **Page tree and authors:** a parent and an order per entity, `children` and `ancestors`; up to 16 authors per entity.
- **Terms:** a term is an entity of its taxonomy's type; `Value::List` holds a post's terms.
- **Scheduled publishing:** `schedule` and `schedule_in` publish or unpublish a locale at a time; one thread per database fires them.
- **Change feed:** `Database::feed` reads committed changes in order (entities, routes, accounts, sessions).
- **Health and observers:** `Database::health`, and an `Observer` for commits, errors, and security events; the `metrics` feature reports them into metrics-lib.
- **Auth:** `account`, identifiers (up to five), roles and permissions, `set_password`, single-use tokens (email verification, password reset, sign-in links, previews), API keys with scopes, recovery codes, and session listing with "sign out that device".
- **Realms and spaces:** `define_realm` with a `RealmPolicy` (lock-out, session limits, pending verification), `define_space`, and one commit across them.
- **Serializable commits:** `commit_serializable` also checks what the closure read by key.

## Changed

- Content sections are format 2, entity heads format 5, and account records format 3; stores and logs written by 0.1 to 0.3 still read.
- A log record holds one section per collection.
- A commit that loses a conflict waits for the winner to be visible before it runs again.
- Publication times strictly increase within a database.

## Fixed

- Editing an entity stored by 0.1 to 0.3 no longer loses its published body.

## Not yet

- TOTP and passkeys wait for crypt-io 1.5 (HMAC-SHA1, ES256 and RS256 verification); they arrive in 0.5, or in a 0.4 patch release if it lands first.
- Devices, descendant paths following a moved parent, sticky posts, `revert`, releases, and assets come later.
- Derived indexes (routes, listings, the page tree, types, schedules) are rebuilt at open, until lsm-db scans lazily.
- The milestone's exit, James's site serving its pages from nex-db, waits for the site's adapter; `examples/site.rs` stands in on every platform.

## Checked

The local gate on Windows and Linux (stable and Rust 1.85), CI on Linux, macOS, and Windows (x64 and ARM), the kill test, and the loom models.
