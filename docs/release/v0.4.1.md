# nex-db 0.4.1 - Second factors

TOTP and passkeys, which waited for crypt-io 1.5, and a fix to content reads. Not published to crates.io.

## What it adds

- **TOTP** (feature `mfa`): `add_totp` (a secret shown once, as base32 and an `otpauth://` URI), `confirm_totp`, `check_totp`, `remove_totp`, and `verify_totp`. Codes are what authenticator apps show (HMAC-SHA1, six digits, 30 seconds); each works once. `sign_in` answers `SignIn::NeedsSecondFactor { challenge }` for an account with TOTP on, and `verify_password` answers `Login::NeedsSecondFactor { account }`.
- **Passkeys** (feature `mfa`): `passkey_registration` and `add_passkey` to register, `passkey_sign_in` and `verify_passkey` to sign in, `passkeys` and `remove_passkey`. nex-db checks the client data, the RP ID, user presence and verification, the signature (`ES256`, `EdDSA`, `RS256`), and the signature counter.
- The `mfa` feature is off by default: it builds crypt-io's AWS-LC backend, which needs a C compiler (on Windows x86-64 no NASM).

## Changed

- crypt-io 1.5.

## Fixed

- A content read could fail with `Error::Corrupt`, or see a commit early, while a commit of the same entity applied.

## Notes

- An account with TOTP on never signs in on its password alone, in any build: one without `mfa` answers `NeedsSecondFactor` and cannot complete it.
- Passkey attestation is not checked.

## Checked

The local gate on Windows and Linux (stable and Rust 1.85, with `mfa`), CI on Linux, macOS, and Windows (x64 and ARM), and `cargo deny`.
