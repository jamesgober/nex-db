# nex-db 0.5.0 - Feature complete

Split auth, per-account keys and erasure, search, and backups. Not published to crates.io.

## What it adds

- **Split auth** (feature `split-auth`): `Database::builder(dir).auth(AuthMode::separate_process())` runs the auth engines in a process of their own, started from the application's program, whose `main` calls `nex_db::serve_auth_process()` first. The application keeps the one commit log and the content engines and holds no auth key, session, or password hash; the auth parts of the log stay sealed. The same calls work in both modes, a commit across auth and content stays atomic, and a database opens in either mode. If the auth process dies or stops answering, auth calls fail and writes stop.
- **Erasure**: each account's private records (its record and password hash, TOTP secret, recovery codes) are sealed under a data key of its own, kept in `auth/account-keys` and never in the log. `erase_account` removes the account's records and destroys the key, so no copy can be read again; its sessions end as `Revoked { Erased }`.
- **Search**: `Type::searchable(weight)` and `Content::search(locale, &Search)`: every word of a query in a published body of one locale, ranked by BM25 over the weighted fields; English locales match word forms and skip common words.
- **Backups**: `Database::backup(dir)` while the database runs (later backups into the same directory add the commits since) and `nex_db::restore(backup, into, RestorePoint::Latest | At(time) | Position(p))`. Revocations committed after the restore point are applied again when the restored database opens.
- **Content**: sticky entities and `Listing::sticky_first`, `Listing::outdated(locale)`, `get_many`, `stream`, `add_redirect`, and `remove_route`.

## Changed

- Entity heads are written in format 6, types in format 3, log records in format 2 (with the commit time). The formats before still read.
- `translate` records the source revision on every call.
- `auth/LOCK` guards the auth files.

## Notes

- A backup can only be extended while the live log still holds its last commit; back up more often than the log fills `checkpoint_every`, or start a new backup directory.
- Content is not encrypted at rest in this version, so backups hold it as stored.
- In split mode a validation crosses a pipe and takes tens of microseconds; a faster channel is planned for 0.6.

## Checked

The local gate on Windows and Linux (stable and Rust 1.85, every feature set), CI on Linux, macOS, and Windows (x64 and ARM), and `cargo deny`.
