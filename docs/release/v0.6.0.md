# nex-db 0.6.0 - Optimisation

Faster session checks and content reads, read hits that allocate nothing, and canary routes. Not published to crates.io.

## What changes

- **Session table**: entries stay in cells that never move and are found with one index probe. Memory per entry is about half what it was at a million sessions, and checks of unknown tokens are faster. Token parsing goes through a lookup table.
- **Content reads**: each space keeps up to 4,096 entities' published entries decoded, so serving a page again needs no store read and no decode. Cloning an `Entry` shares its fields instead of copying them.
- **No allocations on read hits**: a session check (live or unknown token), a route lookup, and a read of an entry served before allocate nothing. `tests/alloc.rs` checks this with a counting allocator.
- **Split auth**: replies are read through a buffer and written in one write each.
- **Canary routes**: `add_canary(site, path)` marks a path nothing is served at. `resolve` answers `None` for it, as for any unknown path, and raises `SecurityEvent::CanaryRequested`. Route records gain kind 4.
- **Benchmarks**: memory per session and per page, recovery, uncached reads, and a comparison with the standard map.

## Fixed

- A read could see a commit that was applied but not yet visible, and an older version on the next read.
- Two reads of one entity or account in one `db.read` could disagree when a commit applied between them.

## Notes

- Not every performance target in the design is met yet. The gaps and their plans are recorded for the next versions.
- Route records of kind 4 (canaries) are not understood by 0.5.0 and earlier.
