# nex-db 0.7.0 - Hardening

Fuzzing, attack tests, a soak test, decoy tokens, and no third-party
dependency outside crypt-io's cryptography. Not published to crates.io.

## What it adds

- **Decoy tokens**: `plant_decoy()` gives a token that names no session, for
  places only an attacker would use it. Validating it answers
  `Validation::Unknown`, as for any token never issued, and raises
  `SecurityEvent::DecoyPresented`; `revoke` retires it.
- **Fuzzing**: every decoder of outside data (log records, engine sections,
  stored records, checkpoints, the backup manifest, the root key file, tokens,
  passkey replies, and the split-auth channel) runs under a cargo-fuzz target
  (`fuzz/`) and a stable-Rust test of generated and mutated inputs on every CI
  platform.
- **Attack tests** (`tests/attacks.rs`): a stolen directory and backup hold no
  identifier, password, or token; no call shows a password hash; known and
  unknown identifiers take the same time to fail; a lock-out survives a
  restart; guessed tokens are never accepted; the engines never reach each
  other.
- **Soak test** (`tests/soak.rs`): a mixed workload with checks, five seconds in
  CI and hours on request.

## Changed

- wal-db 1.2 and lsm-db 1.2 (and error-forge 1.1 through them): no
  third-party crate comes in outside crypt-io's cryptography. On-disk formats
  and checksums are unchanged.

## Fixed

- Builds of one engine alone (`--no-default-features --features auth` or
  `content`) had dead-code warnings.

## Checked

The local gate on Windows and Linux (stable and Rust 1.85, every feature set),
CI on Linux, macOS, and Windows (x64 and ARM), the loom models, `cargo deny`,
cargo-fuzz for 15 minutes, the kill test (1,000 rounds on Linux, 500 on
Windows), and the soak test for an hour on Linux.
