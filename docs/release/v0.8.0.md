# nex-db 0.8.0 - Alpha

Read replicas, signed audit exports, a simpler API, a faster split-auth
check, and a round of security and data-safety fixes in the auth engine. Not
published to crates.io.

## What it adds

- **Read replicas.** `db.ship(after, out)` writes the commits after a position
  as a shipment; `nex_db::open_replica(dir)` opens a directory restored from a
  backup of the primary, and `replica.receive(from)` commits the shipment's
  records in order, through the path a local commit takes. The application
  carries the bytes. Shipments are sealed end to end and checked to extend the
  replica's own history. A replica serves the database's reads, refuses writes
  (`Error::ReadOnlyReplica`), and its directory opens as a database to promote
  it.
- **Signed audit exports** (feature `audit-export`): `db.auth().audit_export(ids)`
  verifies the realm's audit chain and signs a range of it with an Ed25519 key
  derived from the root key; an auditor checks it with the realm's public key
  alone.
- **One-line Tier 1:** `db.content().put(entity)` creates and publishes;
  `db.auth().sign_up(identifier, password)` hashes and creates.

## Changed

- Plain names: `Rid` is `EntityId`, `Login` is `PasswordCheck`, `Entry::rid()`
  is `Entry::id()`, `Hit::rid()` is `Hit::entity()`. The old names stay,
  deprecated, through 0.8. `Change::EntityChanged { rid, .. }` is
  `{ entity, .. }`: rename the field in patterns.
- Split auth: a request reads its own reply from the auth process. A session
  check over the channel takes a median of 5.6 to 6.0 us on Linux and 11 to
  27 us on Windows (8.1 to 8.3 us and 20 to 37 us in 0.7.0).
- wal-db 1.4 for the commit log: a sync flushes every segment written since
  the last one, and an open flushes every segment before recovery reads it.
  With wal-db before 1.4 a commit could return `Ok` with part of it still
  only in the page cache.
- lsm-db 1.3: prefix scans seek to the prefix; a dropped store keeps
  unflushed writes; a failed flush keeps its buffer; directories are synced
  on Unix.

## Fixed

- A lock-out checks no password and answers alike for every one (before, the
  right password answered differently, and guessing went on); second-factor
  checks count toward it; it commits nothing and ends no session; unknown
  identifiers lock out like known ones.
- A decoy raises the alarm from `revoke`, `rotate`, and `redeem`, and stays
  planted until `retire_decoy`.
- `rotate` refuses a session past its idle limit.
- Reset requests for unknown addresses take no room in the session table;
  one account holds at most 1,000 sessions and 16 single-use tokens.
- A checkpoint can no longer destroy the data key of an account being
  created.
- `add_totp` on an account with TOTP on keeps the factor in force until the
  new secret is confirmed.
- Password hashes are limited to 64 MiB, 8 passes, and 4 lanes per check.
- A delete removes revisions written in the same commit.
- Split auth refuses `Keys::env`, wipes every frame in both processes, makes
  no allocation per session check, gives checkpoints and backups an hour,
  and answers an oversized reply with an error.

- The README and crate-level examples resolved a draft that was never
  published.
- The scheduling thread allocated on every pass.
- A prefix of only `0xFF` bytes scanned nothing.

## Migrating from 0.7

Replace `Rid`, `Login`, `.rid()` as above (the compiler points at each use),
and rename `rid` to `entity` in `Change::EntityChanged` patterns. A 0.7
database opens as it is. 0.8 writes a new session checkpoint format, a new
TOTP record format, and a new log operation (an evicted session), so a
database 0.8 has written does not open in 0.7. Split auth now needs the key
in a file (`Keys::file` or `Keys::in_directory`), not `Keys::env`. The audit
chain is not encrypted (see `docs/API.md`).

## Checked

The local gate on Windows and Linux (stable and Rust 1.85, every feature set),
CI on Linux, macOS, and Windows, the replica simulation for 20 seeds of 2,000
rounds, the split-auth tests 30 times on each platform, and the kill test.
