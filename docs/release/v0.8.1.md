# nex-db 0.8.1 - lsm-db 1.4

The account and content stores move to lsm-db 1.4, which fixes several ways a
store could lose data on open. Not published to crates.io.

## Changed

- A store whose manifest is missing or unreadable is never treated as a new
  store, and nothing in it is deleted; lsm-db 1.4 also offers an explicit
  rebuild from the run files.
- A store directory is locked for its handle's life.
- A run's footer is checked when it opens, and new runs carry a footer
  checksum, so a damaged entry count can no longer abort the process at
  compaction.
- A failed compaction leaves no temporary file behind, and its error can be
  read.
- The block cache counts the bytes it holds.

nex-db opens each store once, under its own directory lock, so none of this
changes what it does; it removes those failure modes underneath it.

## Upgrading

Nothing to change. Stores 0.8.0 wrote open as they are, and a store 0.8.1
writes still opens in 0.8.0.

## Checked

The local gate on Windows and Linux (stable and Rust 1.85, every feature
set) and CI on Linux, macOS, and Windows.
