# nex-db 0.9.0 - Deploy

Two-step sign-in without a C compiler, and tighter account checks in the auth
engine. Not published to crates.io.

## Added

- Feature `totp`: TOTP on crypt-io 1.7's pure-Rust code, with no C compiler,
  so a static musl build can offer two-step sign-in. Feature `passkey` keeps
  passkeys on crypt-io's C backend. `mfa` turns on both, as before.
- `Session::id()`: the id `sessions(account)` lists for a validated session,
  to mark "this device" or sign out the others. `validate` is no slower.
- `db.auth().api_keys(account)`: an account's API keys with their dates and
  scopes, never their text.

## Changed

- `issue_session` refuses an account that is locked out, suspended or
  banned, even when the application does not check first.
- `add_totp` is refused while TOTP is on. To move to a new secret, turn TOTP
  off with `remove_totp` first. A second enrolment can no longer replace the
  secret the user has.
- crypt-io 1.7.

## Upgrading

- A build that used `mfa` only for TOTP can switch to `totp` and drop the C
  compiler.
- Code that called `add_totp` to move an account with TOTP on to a new secret
  now gets `Error::Invalid`; call `remove_totp` first.
- Code that issues sessions directly now gets `Error::Invalid` with
  `reason = "may not sign in"` for a blocked account.
- Formats are unchanged: 0.8 databases open as they are.

## Checked

The local gate on Windows and Linux (stable and Rust 1.85, every feature
set), the TOTP feature set built and tested for musl with no C compiler, and
CI on Linux, macOS, and Windows.
